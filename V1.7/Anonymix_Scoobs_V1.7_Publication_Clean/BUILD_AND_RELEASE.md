# Anonymix Scoobs V1.7 — publication source

This is the publication source variant of V1.7. CODE_MAP.md explains file ownership, audio flow and thread handoffs. Keep the diagnostic V1.7 development variant as the baseline for V2.0. The application does not emit its own console or SDL diagnostic messages. The callback timing probes, FFT/level benchmark counters, periodic UI reports and the unused audio diagnostics header are removed. The DSP effects, audio modes, recording, playback, WAV export, visualizers and 60 Hz frame scheduler remain in place.

## Build with Visual Studio Community 2026

1. In a copy of the working project, replace **all** application `.cpp` and `.h` files with `src/`. Remove `AudioDiagnostics.h` from the Visual Studio project if it was explicitly listed; it is absent from this source set. Add any new `.h` files from `src/` that the project does not automatically discover. Do not keep old application `.cpp` files alongside these replacements.
2. Keep the existing SDL3, SDL3_ttf and PortAudio include directories and linker libraries. Build **x64 / Release / C++20**. If the project uses precompiled headers, disable them for these replacement `.cpp` files or integrate them into the project's precompiled-header setup.
3. Run the resulting Windows `.exe` and test Recording, Play, Save WAV, Stream, Shared, Exclusive, mode switching and Reopen Audio. There is no Windows executable in this ZIP: it must be produced by Visual Studio on the Windows machine.
4. For an end-user download, place the tested `.exe`, `runtime/SDL3.dll`, `runtime/SDL3_ttf.dll`, `runtime/portaudio.dll` and `runtime/logo.bmp` in the same directory. Copy `runtime/THIRD_PARTY_NOTICES.txt` and `runtime/LICENSES/` into the distribution. Users do not need the `src/` directory. WAV files are written in a `recordings/` directory beside the executable, so extract the application into a writable location.

The previously observed Visual Studio post-build message about missing `pwsh.exe` comes from the local project configuration, not from these source files. If that step fails to copy runtime DLLs, copy them manually as described above. Visual Studio's module-load notifications and messages generated by Windows, the audio drivers or other libraries can still appear under a debugger; the application source cannot suppress those external messages. The release executable itself should be tested outside the debugger.

This candidate has passed local C++20 syntax checks with test headers. It has **not** been rebuilt or run against Windows devices in this environment. Test the Release x64 executable before uploading it to GitHub. Keep the diagnostic V1.7 archive for further development, since this publication source intentionally has no timing logs.
